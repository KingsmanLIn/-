# 论文研读助手

**带着问题读，留下自己的理解。**

论文研读助手是一款面向学生、研究者和长期阅读学术文献的用户的本地论文研读工具。它将 PDF 原文、结构化阅读卡、批注与文献比较放在同一个工作台中，帮助你从研究问题出发，梳理方法与证据，形成自己的判断，并将阅读积累保存为可持续使用的笔记。

阅读与记录可离线使用，AI 参考分析按需启用；支持连接本机模型或自行配置的外部 API，也支持将阅读记录同步到本地 Obsidian 笔记库。

**当前版本：1.3.8 · Windows 10/11 x64**

## 核心功能

### PDF 原文与阅读记录并排呈现

- 支持批量导入 PDF，单个文件最大 80 MB。
- 提供整页适配、宽度适配、缩放与页码跳转。
- 原文与记录栏可拖拽调整宽度，左侧文献栏与右侧记录栏可分别收起。
- 支持按标题、作者和主题搜索，以及在读、完成、归档状态筛选。
- 导入时在本机尝试提取标题、作者、年份、来源与 DOI；识别不到的字段留空，也可手动校正。

### 四步研读与结构化阅读卡

将阅读过程组织为四个阶段，让每一篇论文都留下问题、依据与自己的理解。

| 阶段 | 阅读重点 | 记录内容 |
| --- | --- | --- |
| 定位问题 | 作者研究什么，为什么值得研究？ | 研究问题、文献缺口、主要回答与贡献 |
| 拆解证据 | 方法与证据如何支持结论？ | 数据与样本、概念与变量、研究方法、核心结果 |
| 形成判断 | 结论有多可靠，在哪些条件下成立？ | 稳健性、替代解释、适用边界、自己的疑问 |
| 复述与应用 | 能否独立复述，并连接到后续研究？ | 独立复述、文献联系、下一步行动 |

阅读卡涵盖 13 个记录字段，并针对框架与综述、因果与机制实证、描述与趋势实证、理论模型提供不同的阅读提示。

### 批注、术语与原文定位

- 选中 PDF 文本即可添加批注，也可手动记录当前页的想法。
- 支持论点、证据、疑问、术语四类批注。
- 将原文摘录与自己的理解分开保存，并记录页码。
- 支持设置文内页码偏移，区分 PDF 页码与论文印刷页码。

### 文献比较与 Markdown 导出

- 按研究问题、数据与方法、主要结果、结论边界、研究联系并列表格，辅助整理综述线索。
- 支持按主题或作者筛选比较范围。
- 阅读卡与文献比较表可导出为 Markdown，便于继续整理和复用。

### Obsidian 笔记库同步

- 将阅读卡、批注与 PDF 原文附件同步到本地 Obsidian 笔记库的专用文件夹。
- 支持保存记录时自动同步，也可手动同步全部文献。
- 同步时保留笔记中的“我的补充”及自动生成区域之外的内容。
- 删除软件内的论文不会删除已经同步到 Obsidian 的笔记与附件。

### 可选的 AI 参考分析

- 支持 Ollama、LM Studio，以及使用 HTTPS 的 OpenAI 兼容接口。
- 按阅读卡结构生成参考分析，与自己的阅读记录分开呈现。
- 对模型返回的证据引文进行原文核对，并标注需要人工确认的内容。
- 长论文超过单次输入预算时自动分段处理，记录实际送入模型的页范围。
- 支持暂停 AI 请求与取消任务；默认不启用导入后自动排队生成。
- 可选读图与图表分析，需支持图片输入的模型与接口，以及本机可用的 Poppler 渲染工具。

AI 参考用于辅助理解与核对。研究判断、引文使用和最终结论仍需回到原文确认。

### 本地备份与迁移

- 文献库默认保存在软件目录下的 `data/`。
- 支持导出完整 ZIP 备份，包含 PDF 原文、阅读卡、批注、AI 分析结果与抽取缓存。
- 恢复备份时补入当前库缺少的文献，保留已有同编号记录。
- 也可在退出软件后复制 `data/`，迁移到另一份软件副本。

## 快速开始

### 便携版

1. 下载 `论文研读助手-本地版-1.3.8-完整便携版.zip`。
2. 将压缩包完整解压到可写目录，例如 `D:\论文研读助手`。
3. 双击 `启动论文研读助手.vbs`；若无法运行，使用 `启动（备用）.bat`。
4. 软件会在默认浏览器中打开，地址通常为 `http://127.0.0.1:8765`。
5. 点击“导入 PDF”，即可开始阅读、批注和填写阅读卡。

便携包自带 Python 运行时与 PDF.js，无需额外安装 Python。基础阅读和记录功能不依赖模型服务，也不需要网络连接。

退出时请使用“保存并退出软件”。直接关闭浏览器标签页不会停止本地后台服务。若端口已被占用，软件会自动选择其他可用端口。

### 配置 AI 参考分析（可选）

在“设置与 Obsidian 同步”中选择连接方式、Provider、模型名称与接口地址。使用本机模型前，请先启动对应的模型服务。

外部 API 的密钥通过环境变量提供；软件设置中只填写环境变量名，不填写密钥值。完成环境变量设置后，重启软件，再对需要分析的论文发起生成请求。

图表分析需额外准备可通过 `PATH` 找到的 `pdftocairo` 或 `pdftoppm`，并使用支持图片输入的接口，例如 LM Studio 或其他 OpenAI 兼容接口。当前 Ollama 自有协议适配器不发送图片；缺少渲染工具时，分析会继续以文字输入进行。

## 数据与隐私

- **本地保存**：PDF 原文、阅读记录、设置和 AI 分析结果保存在软件目录下的 `data/`。
- **离线阅读**：不启用 AI 时，阅读与记录无需向模型服务发送论文内容。
- **按需使用模型**：默认不自动生成 AI 分析；主动生成或自行启用自动排队后，内容会发送给你配置的模型服务。
- **本机模型**：连接本机回环地址上的模型服务时，论文内容不出本机。
- **外部接口**：使用远程模型服务时，分析所需的论文文本及启用读图后选中的页面图片会发送到该服务，留存与计费取决于服务商。
- **密钥管理**：密钥在运行时从环境变量读取，不写入文献库、备份、日志或导出文件。
- **无遥测**：软件不包含遥测功能。

## 当前范围与限制

- 当前发行版支持 Windows 10/11 x64，尚未提供 macOS 版本。
- 扫描件可以人工阅读和记录，但没有文本层时不能直接生成 AI 参考分析；当前未提供内置 OCR。
- 文献信息提取属于有限范围的自动识别，仍需人工核对。
- 长论文分析受输入与请求预算限制，实际覆盖范围以阅读卡中的“输入范围”为准。
- 图表分析依赖多模态模型、兼容接口与本机渲染工具。
- 当前没有独立的公式解析与推导功能，也不支持自动更新。

## 技术实现

采用 Python 3.12 标准库后端、原生 HTML/CSS/JavaScript 前端与 PDF.js 阅读组件，通过本机服务在浏览器中提供工作界面。便携包包含运行所需的 Python 环境与 PDF.js 资源。
