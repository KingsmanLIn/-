# 1.3.6 改动与验证

本轮只修一个用户报告的**布局缺陷**：记录栏（右侧记录/阅读卡面板）掉到原文下面，两栏变成上下分页。

---

## 一、原因

1.3.5 的 UI 整理在两栏之间加了一条可拖拽分隔条 `#splitter`，它成了 `.workspace` 的**第三个**网格子元素：

```
.workspace 的直接子元素： .pdf-panel（原文） | #splitter（分隔条） | .notes-panel（记录栏）
```

而桌面断点里只声明了**两条列轨道**：

```css
@media(min-width:931px){
  .workspace{grid-template-columns:minmax(0,var(--pdf-split,67%)) minmax(0,1fr); …}
}
```

网格自动排布（`grid-auto-flow: row`）会把第三个子元素放到**第二行**——记录栏于是掉到原文下方，而且因为第二行是隐式行（高度 auto），它只剩很矮的一条。窄屏（≤930px）本来就是上下布局，所以这个缺陷只在宽屏出现，容易被忽略。

## 二、修法

列轨道数与子元素数必须一致，给分隔条一条自己的轨道：

```css
.workspace{grid-template-columns:minmax(0,var(--pdf-split,67%)) 14px minmax(0,1fr); …}
```

- 中间那条 14px 轨道归分隔条：宽度与旧的栏间距一致，配合它自身的 `margin:0 -7px`，命中区仍是 14px、正好覆盖两栏接缝；
- 两栏比例不变（默认 67% : 33%）；
- 收起记录栏时记录栏与分隔条都 `display:none`，模板回到 `minmax(0,1fr)` 单列（原文占满）；
- 窄屏仍是上下布局并隐藏分隔条（设计如此，未改动）。

## 五、同轮发现并修掉的另外两处

1. **设置区数字框被通用规则撑成整行宽**（界面不整齐）。`styles.css` 里原先写的 `.settings-number input{width:84px}` 优先级是 (0,1,1)，而设置对话框的通用规则 `.modal-body>label{display:block}` 与 `.modal-body label input{width:100%}` 是 (0,1,2)/(0,1,1)——于是标签与输入各占一行、输入占满整行。改为显式写下 `.modal-body label.settings-number{display:flex;…}` 与 `.modal-body label.settings-number input{width:84px;min-width:84px;margin-top:0;flex:0 0 auto;…}`，优先级压过通用规则。浏览器实测：`same_row: true`、`input_compact: true`（≤120px）、`body_overflows: false`。
2. **开发脚手架被同步进发行包**。UI 子代理自查用的 `static/uicheck-splitter.html` 在删除之前已被一次同步复制进在用版本，并随之进入 1.3.6 的首个构建。已从在用版本删除、重新生成清单，并重新打包（包内 `static/` 现为 7 个文件，`uicheck*` 0 个）。`run/ui_headless_check.py` 这类脚本位于 `run/`（不进包），但它生成的页面会落在 `static/`，因此打包前的 `static/` 检查已列入流程。

## 八、默认分栏比例调整（用户要求）与顺带修掉的「比例棘轮」

**默认值 67% → 58%**（记录栏约 33% → 42%）。理由：默认阅读模式是「适合页面」，按高度缩放后 A4 页只占约 470px，而原文栏分到 824px——多出来的宽度是空的；同时阅读卡（真正要写字的地方）只有 392px。改后 1500px 窗口下实测：原文栏 **713px**、分隔条 14px、记录栏 **503px**（+111px 给阅读卡）。

默认值出现在三处，必须一致，否则「首屏（CSS 回退）」与「拖动后（JS）」会不同：
app.js 的 `const SPLIT_DEFAULT=58`、reader-layout.css 的 `var(--pdf-split,58%)`、index.html 里分隔条的 `aria-valuenow="58"` 占位。新增 `tests/test_layout_contract.py::DefaultSplit` 断言三者相等、并落在 45–75 的合理区间（过低会饿死阅读卡，过高会饿死原文栏）。

**顺带修掉一个真实缺陷——「比例棘轮」**：`applySplit()` 把「按当前窗口夹取后的比例」写回了状态 `splitRatio`。页面的首次布局常常发生在窗口还小的时候（实测 headless 默认窗口 800×600，或用户还没放大窗口），当时夹出来的值会被当成用户意图；之后视口变大，代码只在**这个已被夹过的值**上再夹一次，于是两栏永久停在被压扁的比例上——用户会看到原文栏变窄、比例怎么都不回默认。

- 修法：状态里始终保留用户的意图值，夹取结果只用于渲染；只有 `now=true` 的真实用户操作（拖动/方向键/双击复位）才写回状态与 localStorage。
- 验证（真实浏览器）：`tests/ui_layout_check.py` 新增 `after_narrow_restore` 断言——窄视口走一圈再放大，比例必须回到默认值。**修复前**跑：`pdf_share_percent: 52.4`、`ok: false`；**修复后**跑：`pdf_share_percent: 58.0`、`ok: true`。
- 这个缺陷同时解释了「截图与实测不一致」：截图脚本的页面在 800×600 的默认窗口下先完成了布局（比例被压到约 40%），所以画面上两栏比例看上去是反的；改为「先设定视口再加载页面」后截图与测量一致。
