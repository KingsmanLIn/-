## 2. 公式解析与推导：独立成功能，并显著提高准确度

**现状（已核对，这是"能力太弱"的真实原因）**
- **代码里完全没有公式处理**：全仓库搜索 `formula/equation/LaTeX/math/公式` 只命中 `metadata.py` 里一个无关的期刊名关键词。
- 公式目前只能靠**文本抽取**碰运气：首选 `pdftotext`，失败回退内置解析器或 `pypdf`。数学排版（分式、上下标、希腊字母、矩阵、求和号）在文本层里通常是**错位甚至丢失**的——例如 `Σ` 变成 `P`、`∂` 变成乱码、上下标被拉平、分式断裂成两行。**没有 LaTeX、没有符号表、没有推导**，阅读卡里的"方法/变量"字段只是对文字的概括。
- 好消息：读图管线已经建好且验证过（`figures.py` 选页 + poppler 渲染 PNG + `providers._user_content()` 多模态载荷 + `reading_card.figure_note()` 提示词 + 图片页引文规则 `quote_in_figure`），公式功能可以**直接复用这套骨架**，不必另起炉灶。
- 本机 poppler **含 `pdftohtml`**（明天会用到：它的 XML 输出保留每个字符的坐标与字体大小，是重排分式/上下标的关键），以及 `pdftoppm`、`pdftocairo`、`pdfimages`、`pdftotext`。

**目标**
- 阅读卡里新增一个**独立入口**（例如「公式推导」按钮/标签页），点击后**只针对论文的公式部分**做解析与推导，不影响现有 13 字段阅读卡。
- 输出：这一页/这一步在做什么、LaTeX 转写、符号表（符号→含义→来源页）、推导步骤（每步一行，标注依据页与公式编号）、每一步的性质（定义/代入/求导/一阶条件/稳态/比较静态）、以及**不确定或无法核对的步骤明确标注**。

**明天怎么做（建议按此顺序，先打通再谈准确度）**
- [ ] **P1 选段**：新模块 `formulas.py`。
  - `formula_pages(pages)`：用文本标记定位公式页——`equation`/`eq.`/`Appendix`/行首编号 `(1)`~`(99)`、密度标记（`=`、`∂`、`Σ`、`∫`、`α-ω`、`\frac` 残留）、以及"公式独占一行且上下有索引编号"的排版特征。
  - 复用 `pdftohtml -xml` 的 **block/line/word 坐标**，把疑似公式行按 y 坐标聚成"公式块"，并把编号 `(N)` 作为锚点。
- [ ] **P2 渲染（公式专用参数）**：现有页面渲染是 130 dpi 彩页（够看图，不够看上下标）。公式要**局部高倍**：`pdftocairo -r 220~300` 裁剪公式块外扩 8–12pt 的区域；必要时对同一公式出两张（整页定位 + 局部高倍）。写入 `figures.py` 或新函数，共用超时与体积上限。
- [ ] **P3 独立任务类型**：`analysis.py` 里新增 `kind="formulas"` 的作业路径（沿用同一套：批准/额度/进度/失败码/快照冻结），结果写 `data/formulas/<paper_id>.json`，路由 `POST /api/analysis/<id>/formulas`、`GET /api/formulas/<id>`；设置新增 `settings.ai.formula_vision`（默认开）与 `formula_max_pages`（建议 4–8）。
- [ ] **P4 专用提示词（准确度的核心）**：新 `FORMULA_SYSTEM_PROMPT` + 两段式请求：
  1. **转写**：先只做 LaTeX 转写（不要解读），逐符号对齐图上所见，遇到看不清的写 `\text{?}`；
  2. **推导**：再基于转写给出步骤，**每一步必须写明依据**（页 + 公式编号 + 上个式子的编号），禁止跳步、禁止引入原文没有的假设。
- [ ] **P5 自检与交叉验证（把"准确度"变成可检查的东西）**
  - 让模型对每个推导步骤做一次**独立复核**（第二次请求，temperature 0）：给转写 + 步骤，问"这一步能否由前一步严格得到？不能则指出"；不一致的步骤标记 `unverified`。
  - **量纲/极限自检**：要求给出符号量纲与两三个极限情形（如 α→0、σ→1）的结果，与推导结论对照。
  - **数值抽查**：对可代入的式子给一组数值，检查左右两边是否相等（模型只做算术，程序只做等值比较，不引入符号计算依赖）。
  - 复用现有引文策略：文本层能逐字核对的引文照常计入"已核对"；只在图片里的内容走 `quote_in_figure`（标记待人工核对）；**无法核对的推导步骤一律显式标注，不伪装成已核实**。
- [ ] **P6 界面**：论文操作区加「公式推导」按钮 + 结果面板（LaTeX 用纯文本/等宽字体渲染即可；不要求引入 MathJax；若要，`vendor/` 里加本地副本，不联网 CDN）。
- [ ] **P7 测试**：`tests/test_formulas.py` —— 公式页识别（合成页文本）、渲染命令与局部高倍参数、载荷结构（图片块）、提示词包含"只转写/逐步依据/不确定标注"、量纲与等值检查逻辑、`unverified` 传播、无 LaTeX 能力时的降级（只给符号表 + 步骤，不假装有转写）。
- [ ] **P8 真实评测**：用你库里那篇 19 页「The effects of a money-financed fiscal stimulus」做一次真跑（该文正文与附录含较多公式），把结果与原文逐式对照，记录命中率；再挑一篇公式密集的论文做第二轮。

**验收**
- 点「公式推导」只跑公式相关页，产出 LaTeX 转写 + 符号表 + 分步推导 + 每步依据页码；无法核对之处明确标注。
- 对同一篇论文，转写与原式的**明显错误率**应有可量化下降（建议以"人工逐式核对 30 式，错误 ≤3 式"作为首轮目标）。
- 现有阅读卡功能与 209 项测试不受影响。

**风险**
- 复杂度主要来自**数学排版的图形化本质**：分式/根号/矩阵没有可靠文本表示，必须靠高倍裁剪 + 模型视觉，成本与耗时都高于普通读图（单页 220–300 dpi 约 0.3–1 MB）。
- 模型对推导的自检并非形式化证明；文档与界面必须表述为"参考推导"，与现有"AI 参考分析"的定位一致。

## 5. macOS 移植

**现状（已核对的 Windows 专用点）**

| 文件 | Windows 专用实现 | macOS 需要替换为 |
|---|---|---|
| `launcher_pipe.py` | 当前用户独占**命名管道** + `ctypes.windll.advapi32`（文件里已注明 "named pipes are Windows-only"） | Unix domain socket（`AF_UNIX`，权限 0600）或一次性令牌文件（0600）+ 校验 |
| `launch.py` | `ctypes` 弹 MessageBox、令牌/进程相关调用、`CREATE_NO_WINDOW`、`.vbs`/`.bat` | `osascript` 或 `tkinter` 提示框；`.command`/shell 启动器；`webbrowser.open` |
| `pdf_worker.py` | **Job Object** 限制子进程 CPU/内存 | `resource.setrlimit`（RLIMIT_CPU/AS）+ 子进程超时 |
| `server.py` | `powershell.exe` 目录选择、MessageBox 对话框、`CREATE_NO_WINDOW` | `osascript -e 'choose folder'`（或 tkinter）；无窗口标志在 POSIX 上传 0 即可 |
| `figures.py` | `CREATE_NO_WINDOW` | 同上（`getattr(subprocess,"CREATE_NO_WINDOW",0)` 已可移植，只需确认路径） |
| `credentials.py` | 从注册表 HKCU 读取（历史上用 winreg） | 只保留**环境变量**来源（`PAPER_READER_*`）；可选支持 macOS Keychain（`security find-generic-password`），默认不引入 |
