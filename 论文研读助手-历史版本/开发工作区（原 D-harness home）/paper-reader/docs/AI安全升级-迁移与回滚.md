# 论文研读助手 1.3.1 AI 安全升级 — 迁移、兼容与回滚

面向把 1.3.1 升级到本次安全加固版本的人。三件事：**数据怎么迁移**、**旧配置怎么办**、**怎么回退**。

---

## 1 数据兼容性

| 数据 | 变化 | 是否无损 |
|---|---|---|
| `library.json` | **版本号不变，仍是 v2** | 是。人工字段、阅读步骤、批注、`pageOffset`/`pageLabels`/`lastPage`、`revision`、同步内容全部逐字保留。 |
| `settings.ai` | 新增 `mode`、`max_output_tokens`、`limits{…}`、`credential_revision`、`config_revision` | 是。旧库缺失的键由校验器补默认值，不会丢旧值。 |
| `settings.ai.api_key_env` | 语义收紧为**环境变量名**（裸名字自动规范化为 `env:NAME`） | 是。旧库里存的若确实只是变量名，继续可用。 |
| 旧库中的明文密钥字段 | **不再读取，也不再写入** | 是（记录不丢，只是不再使用）。界面会提示存在旧明文配置及其位置，由你自行删除。 |
| `paper.analysis` | 状态机新增 `waiting_for_user` 语义（重启/恢复后等待确认） | 是。字段集不变，旧记录全部保留。 |
| `data/analyses/<id>.json` | 答案文件现在必须带 `source` 标记与重核验结果 | 旧文件保留可读；恢复/展示时会重新核对，未通过则标为「未重新核对」。 |
| `data/extracted/<id>.json` | 抽取缓存在**恢复路径**上不再被信任 | 缓存文件会被重建，其余场景不变。 |
| 新增 `data/job-ledger.json` | 批准、任务快照、请求/费用记录 | 不参与备份；删除它等于清除所有批准与费用记录。 |
| 新增 `data/run-instance.json`、`data/outbound.json` | 公开端口/管道名；目标批准状态 | 不含秘密，可安全删除。 |

**没有 v3。** 架构书建议的 `ai.profiles[]` 形态（多 profile）本轮**未实现**，原因与实际安全检查的对应关系见下节。

### 1.1 关于 v3 profiles 的说明（重要）

架构书 13.1 建议用 `profiles[]` 替代单个全局 `api_key_env`。本轮**没有**改这条结构，理由：

- 单 profile 下，「一次任务只使用一个冻结身份」已经成立：任务快照绑定 `profile_id`（由目标身份派生）、`target_identity`、`credential_ref`、`config_revision`、`credential_revision`。
- 批准与预算绑定在**目标身份**上，而不是绑定在「唯一的那个开关」上；换目标即失效。
- 引入 `profiles[]` 会改变已发布的库结构（v2→v3），而**本轮没有真实服务商可用来验证多 profile 的切换与计费语义**。在没有验证手段时改结构，风险大于收益。

因此：**库结构保持 v2，多 profile 未实现**。若后续要做，应按「新增 migrations 步骤 + 独立回归」推进，而不是在本轮顺手改。

## 2 升级步骤

1. **备份**：复制整个数据目录（含 `papers/`、`analyses/`、`extracted/`、`library.json`）。升级前程序自己也会写 `library.previous.json`。
2. 关闭正在运行的程序（确认托盘/控制台里没有残留进程，否则旧进程仍占用端口与实例锁）。
3. 用新版本覆盖程序目录（**不要**覆盖数据目录）。
4. 启动。首次启动会：
   - 校验并补全 `settings.ai` 的新键；
   - 把所有已有答案标记为 `stale`（提示词版本升级），需要时重新生成；
   - 清除旧的对某目标的批准（旧库没有批准记录，等于全部需要重新确认）；
   - 写入 `library.previous.json` 作为迁移前的原文副本。
5. 打开「AI 设置」，重新确认连接方式、接口地址、模型和环境变量名，保存。
6. 对一篇**不敏感**的论文点一次「生成参考」，确认外部调用按预期工作。

预期行为变化（不是故障）：

- 已有答案显示为「需要重新生成」；
- 导入 PDF 后论文停在「点击查看 AI 参考」；
- 服务重启后，未完成的论文停在「等待确认」而不是自动继续；
- 旧的明文密钥不再生效，需要改成环境变量引用。

## 3 回滚

回滚**只回退业务代码，不重新开启明文密钥或带 Key 的 HTTP 通道**。

| 目标 | 操作 |
|---|---|
| 回退到升级前版本 | 用备份的程序目录覆盖回来，并把 `library.previous.json` 还原为 `library.json`（或直接用步骤 1 的备份目录）。 |
| 只回退某一步 | 见下方分阶段文件清单。 |
| 保留资料但停用 AI | 不需要回滚代码：把「连接方式」设为本机模型或把 provider 设为「未配置」，并打开「暂停所有 AI 出站」。 |

分阶段回滚清单（删除=新增文件，还原=用升级前副本覆盖）：

| 阶段 | 新增 | 还原 |
|---|---|---|
| 1 凭据与秘密边界 | `credentials.py`、`secret_guard.py` | `providers.py`、`analysis.py` |
| 2 目标策略与传输 | `endpoint_policy.py`、`secure_transport.py` | `providers.py` |
| 3 会话与服务加固 | `session.py`、`launcher_pipe.py` | `server.py`、`static/app.js`、`static/index.html`、`launch.py` |
| 4 任务与预算 | `job_policy.py` | `analysis.py`、`server.py`、`schema.py` |
| 5 内容与恢复 | `backup_guard.py`、`extract_subprocess.py` | `reading_card.py`、`quotes.py`、`server.py` |
| 6 能力适配 | — | `providers.py`、`secure_transport.py` |

**每次生成的调用数**：主请求 1 次 + 修复 1 次；为兼容服务商而重发提示词也算调用，额度不足时程序不会重发。

**不要回滚的部分**（回滚它们等于重新引入已修掉的漏洞）：

- 明文密钥的读取路径（`credentials.legacy_plaintext_status` 只报告、不回读）；
- 无 TLS / 跳过证书校验 / 任意 headers 的开关（不存在）；
- `force=true` 默认值（兼容接口曾默认强制重跑）；
- 写答案与写状态前的"仍是最新任务"判定（去掉它，旧任务会覆盖新答案）；
- 健康检查与模型列表上的暂停/批准判定（去掉它，暂停时仍会带密钥出网）；
- 页面内嵌管理令牌（已改为一次性能力经命名管道发放）。

回滚后必须做的两件事：

1. 把 AI 设为「未配置」或打开暂停，避免旧代码在没有新边界的情况下直接出站；
2. 用**新的安全副本**恢复资料，不要复用升级过程中间状态的 `data`。

## 4 兼容性结论

| 项目 | 结论 | 依据 |
|---|---|---|
| 本机 Ollama 形状接口 | 可用 | 协议桩端到端测试 |
| 本机 OpenAI 兼容形状接口 | 可用 | 协议桩端到端测试 |
| 外部 HTTPS 接口 | 可用 | 协议桩 + 自签证书端到端测试（**未做真实服务商调用**） |
| 服务商不支持某可选参数 | 自动降级：按名丢弃该参数后重试一次 | 阶段 6 测试 |
| 服务商不支持输出 token 上限 | **不降级**，报固定错误并停止 | 阶段 6 测试 |
| 401/403 失效密钥 | 固定错误码，人工阅读继续可用 | 阶段 6 测试 |
| 429 | 使用 `Retry-After` 做有限退避，上限 20 秒 | 阶段 4 测试 |
| 每次生成的调用数 | 最多 2 次；兼容重发也占用额度，额度不足则不重发 | 阶段 6/7 测试 |
| 代理 | 未实现；环境代理变量被忽略，连接始终直连 | 阶段 2 代码与测试 |
| Windows 凭据管理器（wincred） | 未实现（本版本只支持环境变量引用） | 决策 A |
