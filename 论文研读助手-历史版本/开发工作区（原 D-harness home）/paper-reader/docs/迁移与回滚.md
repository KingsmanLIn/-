# 迁移与回滚说明

改造在**独立工作副本** `D:\harness home\paper-reader\` 中进行；线上安装目录
`D:\work\常用软件\论文研读助手-本地版\论文研读助手` 全程未被修改，仍运行 v1。

---

## 一、数据迁移：v1 → v2

### 什么时候发生

服务启动时 `Store` 读取 `data/library.json`，若 `version < 2` 就调用 `schema.migrate_state()`
就地升级为 v2，并用原子写入落盘。整个过程幂等：再次启动不会改变任何既有内容。

### 迁移做了什么

| 位置 | 变化 |
|---|---|
| 顶层 | `version: 1 → 2` |
| `settings` | 新增 `ai: {provider, base_url, model, api_key_env, auto_analyze, max_concurrent_jobs}`，默认 `provider="none"`（AI 不启用） |
| 每篇 `papers[]` | 新增 `analysis` 元数据块（19 个键，状态默认 `none`）；**已有键一律不动** |
| 旧记录缺字段 | 逐个补齐缺失的新字段（例如早于阶段 3 的记录没有 `provider`、`attempt`），不覆盖已有值 |
| 源文件 | 迁移前的原始 v1 字节会另存为 `data/library.previous.json`，可直接用于回滚 |
| 缺失 PDF | 找不到原文的条目只标记，不删除记录 |

### 不会被改动的东西

人工 `fields`、`steps`、`annotations`、`revision`、`lastPage`、`title`、`type`、`note_name`、
`language` 以及 `data/papers/*.pdf` 全部保持逐字节不变（验收测试 `MigrationKeepsHumanWork`
逐条比对）。迁移**不会**自动开启 AI，也不会给任何论文生成分析。

### 备份格式兼容

- 备份 ZIP 的 `manifest.json` 记录版本；恢复 v1 备份到 v2 库时走同一套迁移逻辑。
- 恢复只**补入**当前库缺少的文献，同编号的已有记录保持不变（`revision` 不倒退）。
- `data/analyses/*.json`（已生成的参考）随备份一起走；`data/extracted/`（文本缓存）也包含，
  但它可以随时删除后自动重建。

## 二、回滚

### 情况 A：只回滚某一次改造（保留数据）

| 回滚目标 | 操作 |
|---|---|
| 阶段 7（PDF 布局与分页） | `static/app.js`、`static/index.html` 换回阶段 6 快照，删除 `static/reader-layout.css` |
| 阶段 6（阅读卡 AI 面板） | `static/app.js`、`static/index.html` 换回阶段 5 快照，删除 `static/ai-reference.css` |
| 阶段 5（接口与设置页） | `server.py`、`static/index.html`、`static/app.js`、`使用说明.md` 换回阶段 4 快照 |
| 阶段 4（阅读卡校验） | 删除 `reading_card.py`、`quotes.py`，`analysis.py` 换回阶段 3 快照 |
| 阶段 3（后台任务） | 删除 `providers.py`、`analysis.py`，`server.py` 换回阶段 2 快照并去掉 `--no-worker` |

数据层不需要跟着回滚：v2 的 `analysis` 元数据对 v1 代码是无害的额外键。

### 情况 B：整体回到出厂状态

1. 关闭软件，确认没有残留进程占用 `data/instance.lock`。
2. 把工作副本的 `data/` 整体改名留档（例如 `data.bak-2026xxxx`）。
3. 解压出厂包 `论文研读助手-本地版.zip`（SHA256 `3C0D42CFB0A727E3…`，未被改动）到新目录。
4. 若要恢复阅读记录：把留档的 `data/library.previous.json` 覆盖新目录的 `data/library.json`，
   再复制 `data/papers/*.pdf`；出厂版本会把它当作 v1 正常读取。
5. `data/analyses/`、`data/extracted/`、`data/credentials.json` 可直接删除，出厂版本不会读取。

### 情况 C：只想删掉 AI 痕迹

- 删除 `data/analyses/`（含 `<id>.failed.json`）、`data/extracted/`。
- 把 `data/library.json` 里每篇的 `analysis.status` 置为 `none`（或整块删除，v2 会补默认值）。
- 设置页把 Provider 改回"不使用"。人工 `fields` 与批注不受影响。

## 三、升级前建议

1. 在软件里点"导出完整备份"，把 ZIP 存到库外位置。
2. 复制一份 `data/` 目录（至少 `library.json` 与 `papers/`）。
3. 记录当前 `run/server.json`（端口与进程号），便于确认升级后是否需要重启。
4. 升级后打开任一篇旧论文，确认阅读卡、步骤与批注都在，再开始导入新论文。
