## 4 阶段 2 API 目标和出站连接器

输入：阶段 1、架构书第 5、7 节。  
依赖：凭据已可绑定 profile。  
目标：Key 和论文只发给批准的目标，并仍能连接外部 API。

~~~text
执行阶段 2，修复 F01/F02，建立 EndpointPolicy 与 SecureTransport。

步骤：
1. 明确 local_loopback 和 cloud_https。云模式必须 HTTPS，本地 HTTP 仅限精确回环地址+端口。
2. 解析 URL，拒绝 userinfo/query/fragment/控制字符/非法端口/异常编码/反斜杠。规范化 host、IDNA、端口和 base path。
3. 批准目标采用完整 origin+base path，不能 substring 白名单；正文、响应和重定向不能提供新目标。
4. cloud_https 拒绝不允许的 IPv4/IPv6、映射、内网、link-local、metadata、unspecified、multicast 和保留地址；本机模式只准回环。
5. 对所有 DNS 结果和实际连接 IP 执行策略，并确保校验目标与连接目标一致。保留域名 SNI/hostname verification，不能换 IP 后关 TLS 校验。
6. 使用私有 HTTP client/opener，拒绝全部自动 301/302/303/307/308；健康检查、模型列表和分析用同一 transport。

8. TLS 校验开启，失败固定报错，禁止 verify=False/HTTP fallback。
9. endpoint、端口、模式或 base path 改变时清空该 profile 凭据绑定/外发授权，暂停旧队列。不能把原 Key 试发给新服务器。
10. 先校验授权/endpoint/预算再取 Key，认证仅后端 header，Key 不进入任何 model payload。
11. adapter 按能力构造路径和输出 token 参数；保留本地/外部兼容接口，不允许任意自定义危险 headers。
12. 首版可仅直连；禁止全局DNS monkeypatch/跨profile连接复用，测试包含真实本地TLS socket与SNI/证书/IP证据。base path按段匹配，防urljoin覆盖/编码斜杠。
13. /models不支持不等于Key无效，允许填模型后用户主动做最小限额测试；可选JSON参数按能力适配，后端验证/额度仍强制。
~~~
