# 交给执行 AI 的 1.3.2 整改与复审提示词

你是负责修复论文研读助手 1.3.2 的软件安全工程师。先阅读同目录的《论文研读助手1.3.2-独立安全审查报告.md》和逐项对照表。目标是修复阻断项并提交可复核的补丁与测试证据，不是重新解释报告。

## 硬性边界
- 在隔离副本工作，不修改原始 ZIP、原 D 盘源码或用户数据。
- 不读取真实 API Key、tests/secret.json 值、真实 library/PDF 正文，不调用公网或真实付费服务商。
- 只用合成 PDF、虚构哨兵、127.0.0.1 HTTPS/HTTP stub。报告只记录计数、状态、固定错误码，不写哨兵值、正文或原始响应。
- 不能把静态注释、计划、mock 的 validate 调用或测试全绿当作端到端证据。每个 scanner 必须实际获得合成论文授权并看到 provider request count>0；等待、跳过、授权缺失必须非零失败。

## 实施顺序
1. P0 目标与授权一致性：创建不可变 JobSnapshot，由完整快照构造 adapter、request、context 和发送目标；保存设置、mode、origin、port/base path、model、credential_ref/revision、config_revision、PDF hash 或 prompt revision 任一变化时，在同一锁/事务中撤销旧 target/paper approval、停车 queued/running，并递增 revision。每次 POST 前核验 snapshot 指纹、approval_id、job_id/generation、credential revision；变更后旧任务请求数必须为 0。
2. P0 输出秘密边界：Health/models/request/error 的所有成功和失败 DTO 走同一安全序列化器。模型 id、detail、provider message、headers、URL、错误正文只允许固定字段；限制模型名长度/字符集，任何秘密命中直接返回固定 secret_echo，原值不进入浏览器、日志、library、failure、backup。
3. P1 真实 GUI 设置路径：/api/settings、/api/ai-settings、页面 saveAiSettings 共用一个 schema，不能静默丢弃 mode、limits、output cap、revision。保存后回显 effective config；从真实页面选择 cloud_https、保存、批准、对合成论文首次生成，确认目标收到一次、模式正确。
4. P1 状态机 compare-and-set：所有 transition、fail、retry、repair、outcome 和答案写入带 job_id/generation 条件并原子提交。旧任务只能写自己的 ledger outcome，不能改变当前论文状态。明确 force 是等待旧任务结束还是接管写入权；测试旧 success/旧失败/旧取消/旧 repair failure 晚到四条路径。
5. P1 预算和取消：日窗口不能用固定 journal[-1000:]；保留未过期记录或原子聚合计数，写失败 fail closed。每次实际 retransmit 前再检查 cancel、pause、profile、snapshot、approval 和预算；取消、未知结果、被取代任务不得适配重发。验证最后一个日额度竞争、重启恢复、429、repair、adaptation。
6. P1 严格解析：生产 adapter 只能调用唯一 strict JSON parser；拒绝重复键、NaN/Infinity、超长文本/键、深嵌套、未知字段；repair 和 restore 也用同一 parser，异常映射固定码且不回显 raw model output。
7. P2 传输与 PDF：transport 使用统一 monotonic deadline 覆盖 DNS、连接、headers、body、取消；所有不可信 PDF（普通分析、导入、恢复）使用无凭据受限子进程，加入 CPU/内存/页数/解压/输出硬限制并在超限时中止、清理临时目录。
8. 发布包：从空库或明确许可的匿名 synthetic seed 构建；默认 ZIP 不含 data/library.json、data/papers、logs、ledger、credentials、tests。构建后自动检查成员、敏感值、论文内容；私有用户备份使用单独流程，不能冒充公共安装包。

## 必须新增或修正的验收
- 目标切换：A 入队→改 B→drain，A/B 请求计数、Authorization、snapshot/approval/revision 全部匹配；旧任务 0 请求。
- models 回显：/models 的 data[].id、错误 detail、HTTP headers、成功字段分别放入哨兵；任何浏览器/日志/存储命中均失败。
- GUI：真实浏览器选择云模式并保存，读取的 effective mode 与下一次 request 一致。
- 晚到路径：旧 success、旧 auth failure、旧 cancel、旧 repair failure 均不能覆盖当前 ready。
- 日预算：limit=1001，执行 1003 次只能接受 1001；重启后计数不下降。
- 取消适配：取消首 POST 后返回 400 capability，provider POST 必须仍为 1。
- duplicate JSON：生产入口拒绝并产生固定码。
- scanner：必须 grant_approval 或等价真实用户动作；发送计数>0；terminal state；失败 exit!=0。
- 运行 70 项清单，逐项写自动通过/人工验证/未通过/未验证/不适用；不得将不适用隐藏现有入口。

## 交付格式
提交补丁、迁移/回滚说明、威胁边界、测试日志、逐项清单、发布 ZIP 成员清单和 SHA-256。最终报告必须明确未测试的真实服务商、浏览器、跨用户 ACL、macOS 项目，不得使用绝对安全、零泄露或全部通过。
