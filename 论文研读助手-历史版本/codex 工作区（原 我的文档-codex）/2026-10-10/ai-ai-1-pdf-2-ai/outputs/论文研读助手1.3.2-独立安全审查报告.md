# 论文研读助手 1.3.2 独立安全审查报告

## 结论：未通过发布前安全审查

本版不能作为公开分发包，也不能以“193 项安全套件通过”作为安全完成证明。两个 P0 阻断项是：排队任务换目标后仍把论文和凭据发往新地址；/models 上游内容可把完整 Key 回显到浏览器。另有外部 API 模式保存 bug、旧任务失败覆盖、预算截断、取消后重发、生产 JSON 解析不严格等问题。整改并重新完成真实 UI 和授权后的合成出站测试前，应保持 AI 出站暂停。

## 审查范围与边界

审查对象是 论文研读助手-本地版-1.3.2-全新安装.zip 和 1.3.2-待审清单.json。ZIP SHA-256 为 2d7cc8f2b62532ea527cd6057599fbf85807d43e62867e0495917c521b36c799，清单 SHA-256 为 8b21e7e018336e8ae0133718eb12a9b73163476e64c567fd9631aab605511725，两者一致；24 个关键源文件与清单及隔离审查副本一致。未修改原 ZIP、D 盘源码或用户数据。
未读取真实 API Key、tests/secret.json 的值、真实 data/library.json 或论文正文；未连接真实服务商；所有复现使用合成论文、虚构哨兵和 127.0.0.1 桩。没有运行安装器、启动脚本、build_release.py 或 phase0 快照；没有做真实浏览器、跨 Windows 用户命名管道、恶意巨 PDF 或 macOS 验收。

## 证据与测试解释

隔离安全套件执行 193 项，首次失败 1 项是合成 PDF 只有 8,631 bytes、未满足测试自身“>65,536”前提；补充无害 padding 后针对该测试重跑通过。因此应记录为“193 项套件，夹具修正后相关断言通过”，不能写成完整产品所有测试均独立通过。
phase1 channel scanner 有 19 个扫描通道、泄露计数 0，但终态是 waiting_for_user / consent_required，它没有获得生成授权，不能证明实际发送后的响应边界。phase2 HTTPS scanner 的 15 个 transport/策略步骤通过，最后 manager job 仍 waiting_for_user，所以不是完整 16 PASS。测试使用 loopback bridge 和 mock DNS，不能代替真实云服务商兼容性。

## 独立复现的整改项

### P0-01｜排队任务快照与实际 adapter/目标不一致（P0）

定位：work/review-1.3.2/analysis.py:551-557,720-785; server.py:304-326; job_policy.py:452-481

复现与结果：先以目标 A 入队并批准，再通过真实 POST /api/settings 改为目标 B，drain 旧任务。A 收到 0，B 收到 2 个带认证请求；冻结快照仍为 A，最终状态 failed。

影响：论文正文和凭据会发送到用户未批准的新目标，旧 approval、model/revision 与实际请求可能不一致。

整改与验收：使 adapter 从同一完整冻结快照创建；配置/目标、模型、credential revision、config revision、PDF hash、approval_id 变更时原子撤销旧批准并停车；每次实际 POST 前比较目标指纹和 revision；状态/预算/发送使用同一 job 条件。覆盖 N10/C06/J04/J12。

### P0-02｜/models 模型 id 未经秘密 DTO 过滤而进入浏览器回包（P0）

定位：work/review-1.3.2/providers.py:162,654-658; server.py:1163-1170

复现与结果：回环桩 /models 返回一个已登记的长哨兵值作为 data[0].id，GET /api/analysis 返回 HTTP 200，响应包含完整已知值。

影响：上游异常或恶意网关可把 API Key 写入模型名；完整 Key 进入页面内存、浏览器网络记录和可能的共享响应。

整改与验收：统一 Health/Models/错误/成功 DTO；模型 id 只接受受限长度和字符集，secret_guard 命中立即固定错误并丢弃原文；所有 API 响应做最后秘密拒绝。覆盖 O01/O03/O05/N01。

### P1-01｜GUI 保存外部 API 时静默丢弃 mode 等字段（P1）

定位：work/review-1.3.2/static/app.js:550-559; server.py:1307-1313

复现与结果：UI POST /api/settings 带 mode=cloud_https 和 HTTPS 地址，HTTP 200 返回及存储仍为 local_loopback；/api/ai-settings 与 Store.update 路径行为不同。

影响：用户以为已启用云 API，但真实请求按本机模式判断，外部 API 功能不可用或配置与界面不一致；安全审批也可能针对错误模式。

整改与验收：所有设置入口共用 schema 白名单；保存/读取返回 effective mode、limits、revision；增加真实 GUI 首次生成测试和模式变更审批测试；未知字段固定拒绝而非静默忽略。覆盖 N01/N02/J01/J10/U01/U02/L08。

### P1-02｜被取代任务的失败路径仍可覆盖新任务状态（P1）

定位：work/review-1.3.2/analysis.py:627-629,849-885,1256-1267

复现与结果：旧任务延迟返回 auth_failed；新 force 任务成功为 ready；释放旧任务后状态变为 failed，答案文件仍存在且 current job 是新任务。

影响：UI 显示失败而保留新答案；旧错误可能改变新任务的重试、恢复和可见性，造成 TOCTOU。

整改与验收：所有 transition、_fail、retry、repair、outcome、answer write 都带 job_id/generation 条件，在同一锁/事务中 compare-and-set；旧 job 只能写自己的 outcome；force 明确等待/接管策略并用并发回归证明。覆盖 J02/J03/J04。

### P1-03｜每日预算 journal 固定截断 1000 条（P1）

定位：work/review-1.3.2/job_policy.py:338-349,357-385

复现与结果：daily_request_limit=1001 时执行 1003 次 reserve，全部接受；journal 只保留 1000 条，spend_today 报 1000。

影响：超过 1000 次配置上限后仍能发出请求，重启/滚动窗口下预算可被绕过。

整改与验收：按时间窗口保留全部未过期记录或使用原子按日/按窗口聚合计数；明确持久化恢复与时钟边界；写 ledger 失败必须 fail closed。覆盖 J08/J09/J10。

### P1-04｜取消后 provider 能力适配仍会重发（P1）

定位：work/review-1.3.2/analysis.py:720-785; providers.py:486-525

复现与结果：首 POST 阻塞时取消；首响应 400 response_format unsupported；实际 POST 数为 2，最终状态 cancelled。

影响：取消后仍发送全文并产生费用；界面状态正确但出站事实错误。

整改与验收：统一 retransmit gate：每次传输前检查 cancel/pause/profile/target/revision/预算；取消、未知结果或 job 被取代时不得适配重发；保留已发请求计费，不承诺退款。覆盖 J05/J07/J08/J11。

### P1-05｜严格 JSON helper 未接入生产 adapter（P1）

定位：work/review-1.3.2/reading_card.py:838-865; providers.py:419-436,617-720

复现与结果：同一合法阅读卡附重复 overall：HttpAdapter._load_json 和生产 validator 接受，reading_card.parse_model_json 拒绝。

影响：重复键、NaN、深层/大对象可让解析器与后续验证看到不同语义，绕过预期内容边界。

整改与验收：一个受限 parser 负责 envelope、模型 content、repair 和恢复输入；解析前限长，拒绝重复键/NaN/深度/未知字段；异常只映射固定错误。覆盖 M02/M04/O04。

### P2-01｜传输只有 socket 空闲 read_timeout，没有总 deadline（P2）

定位：work/review-1.3.2/secure_transport.py:94-193

复现与结果：read_timeout=.1，桩每 .03 秒滴送 20 字节，响应成功且耗时约 .625 秒。

影响：慢滴送可长期占用 worker；连接、headers、body、DNS 和取消没有共同总时限。

整改与验收：使用 monotonic deadline，所有 DNS/候选连接/headers/body/取消检查消耗同一预算；超时固定映射并保证连接释放。覆盖 N12/L04/L05。

### P2-02｜短合法凭据不进入 SecretGuard；注册表有固定淘汰上限（P2）

定位：work/review-1.3.2/credentials.py:107-120; secret_guard.py:100-138

复现与结果：5 字符值通过 credentials.validate_value，但 register/contains_secret 不识别；静态还发现 _MAX_TRACKED=32 会淘汰旧值。

影响：短或轮换后的凭据可能在错误、模型列表或输出边界漏检；长运行进程的历史秘密防护不稳定。

整改与验收：使凭据最小长度与 guard 规则一致，或对短值采用精确字段/来源匹配；秘密引用按请求生命周期保留，不能无条件淘汰仍可能出现的值；增加轮换和历史回显测试。覆盖 C05/O05/C06。

### P2-03｜普通分析 PDF 仍在主进程，解压/资源限制不足（P2）

定位：work/review-1.3.2/analysis.py:1043-1053; pdftext.py:559-562,669-672; extract_subprocess.py:48-115

复现与结果：源审查确认普通 _chunks 使用 PdfTextExtractor，只有 restore 路径调用受限子进程；zlib 解压无展开字节上限；子进程没有 OS 内存/CPU/job-object 限制，输出检查在完成后才 stat。

影响：恶意 PDF/压缩流可耗尽主进程 CPU、内存或 worker；主进程环境边界较宽。未运行恶意巨 PDF，因此这是静态风险。

整改与验收：所有不可信 PDF 解析统一进入无凭据受限子进程；设置 OS CPU/内存/输出/页数/解压上限，超限即时中止，finally 清理 scratch；保留人工阅读降级。覆盖 D07/L05。

### P1-06｜发布包带真实用户文库与论文 PDF（P1）

定位：work/review132_intake.json archive_entries; D:/harness home/paper-reader/tests/build_release.py:221-231

复现与结果：ZIP 直接含 data/library.json 和 3 个 PDF；清单明确 warning；build_release 会复制指定 library 及 ROOT/data/papers。

影响：私人自用包与公开分发边界混淆；公开上传会暴露用户论文和阅读元数据。

整改与验收：发布构建必须从空库/用户明确选择的脱敏 seed 开始，默认不打包 data；单独私有备份流程；构建后成员白名单和敏感内容扫描为硬门槛。覆盖 C08/D02/D09。

### P1-07｜扫描器把未授权等待当成零泄露/全通过（P1）

定位：work/review-1.3.2/tests/security/phase1_channel_scan.py:77-80,155-161; phase2_e2e_https.py:176-198; docs/AI安全升级-独立审查与整改.md:107-113

复现与结果：channel scanner 状态 waiting_for_user、consent_required、leaked_channels=[]；HTTPS scanner 15 个传输步骤通过但 terminal job waiting_for_user，报告文档却写 19 channels/16 PASS。

影响：证据没有覆盖实际论文发送/回包，文档会给出过强发布结论。

整改与验收：scanner 必须显式 grant 合成论文授权，断言 provider request count>0 和 terminal state；失败/等待返回非零；报告绑定 ZIP hash/version，禁止把未执行路径计入 PASS。覆盖 N01/O01-O07/J01。

## 发布判定

- 公开发布：阻断。安装包包含真实用户库和 3 个 PDF，必须先重建空库/许可 seed 包。
- AI 外部使用：阻断。P0-01、P0-02 修复并通过合成授权出站回归前，不应启用。
- Windows 私人自用：仍需整改。即使仅限本人使用，也不能接受 Key 回显和目标错配。
- macOS：本轮未验收。当前交付仍按 Windows/Python 工作流审查；macOS 移植需另做钥匙串、沙盒、文件权限、打包和浏览器验收。

## 给执行 AI 的总规则

只在隔离工作副本实现修复；不得读取真实 Key、真实用户库或论文正文，不得调用真实付费 API；测试只用合成论文、虚构哨兵和本地 stub。每个修复必须先写负例再写合法路径，记录请求计数、最终状态、job_id/generation、目标指纹、凭据 revision、预算 reservation 和秘密命中数量；失败或等待不得计为 PASS。禁止把静态注释、计划、mock 函数调用或“测试全绿”当作真实控制证据。
