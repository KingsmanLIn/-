## 三、几点说明

- **没有动 `C:\Users\ASUS\.codex`**：那是 Codex 命令行工具自身的配置、会话与插件目录（一万八千多个文件，含 `.tmp` 缓存），属于工具状态而不是本项目的文件，移走会让 Codex 无法使用。项目相关的 Codex 工作区已收进 `codex 工作区（原 我的文档-codex）/`。
- **`D:\harness home` 现在是空的**，可以直接删除；`C:\Users\ASUS\Documents\codex` 也已不存在（唯一内容已收纳）。
- **开发工具链已改指归档内的新位置**：`pr-lab` 里的打包/校验脚本（`tests/build_package.py`、`tools/build_installer.py`、`sync_to_live.py` 等 17 个）中的路径常量都指向本归档与上一层的最新版，并已从新位置跑通 **211 项离线测试**。以后要改代码或重新打包，直接在 `开发工作区（原 D-harness home）\pr-lab` 里做即可。
- **文献库没有丢**：迁移是把 `data/`（文献库、PDF 原文、AI 答案、抽取缓存）复制到 1.3.8 那份里，归档里的 1.3.3 仍保留原副本；此外 `backups/` 与 `codex 工作区/` 里还各有若干份历史库副本可供追溯。
- **同一个软件可以有多个副本**：即使以后把归档里某份也启动起来，端口会自动错开（8765、8766…），各用各的文献库，互不影响。
- **不要删** `runtime/` 目录：那是自带的 Python 运行时，删了软件无法启动。
- 想彻底清理旧版，直接删掉本文件夹即可；上一层的 `1.3.8版本\` 不受影响。
